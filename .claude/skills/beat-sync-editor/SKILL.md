# Beat-Sync Editor

Собирает бит-синхронный видеомонтаж из (а) музыкального трека и (б) одного
или нескольких исходных видео. Работает в три прохода — каждый со своим
скриптом, каждый производит проверяемый JSON/файл, прежде чем идти дальше:

```
scripts/detect_beats.py   аудио      -> beats.json   (биты, сила, энергия, акценты)
scripts/score_clips.py    видео(-ы)  -> clips.json    (оценённые сегменты-кандидаты)
scripts/build_edit.py     оба json   -> final.mp4     (готовый монтаж)
```

## Когда применять

Пользователь просит смонтировать ролик под музыку, синхронизировать нарезку
с битом, "как в капкате/премиум монтаже", добавить трендовые переходы, или
автоматически выбрать лучшие кадры из отснятого материала под ритм трека.

## Предварительные требования

1. **ffmpeg/ffprobe** должны быть в PATH (`ffmpeg -version`). Это системная
   зависимость, не ставится через pip — если её нет, попроси пользователя
   установить (`apt-get install ffmpeg` / `brew install ffmpeg`) или установи
   сам при наличии прав.
2. Python-зависимости:
   ```
   pip install -r scripts/requirements.txt
   ```
   (librosa, opencv-python-headless, numpy, scipy, soundfile — детектор битов
   и скоринг кадров работают на них, не на эвристиках "на глаз".)

## Пошаговый процесс

### 1. Распознать биты трека

```
python3 scripts/detect_beats.py <music.mp3> --out beats.json
```

Использует `librosa.beat.beat_track` (устойчивый DP-трекер битов, а не
простой peak-picking) плюс:
- нормализованную "силу" каждого бита (`onset_strength` на позиции бита),
- нормализованную локальную энергию (RMS) — по ней определяются
  билд-апы/дропы,
- наивные downbeats (группировка по 4, привязанная к сильнейшему биту
  первого такта),
- отдельный список "акцентов" (`onset_detect`) — резких хитов, которые не
  обязательно лежат на ровной сетке, полезны как триггеры для glitch/flash.

Проверь консольный вывод (BPM, количество битов, длительность) — если BPM
выглядит абсурдно (например, в 2 раза выше/ниже ожидаемого для жанра), это
нормальная особенность бит-трекеров на некоторых треках; можно продолжать —
сетка ловит все актуальные онсеты независимо от того, как трекер назвал BPM.

### 2. Оценить исходники

```
python3 scripts/score_clips.py source1.mp4 source2.mp4 ... \
    --slot-duration 0.5 --out clips.json
```

`--slot-duration` задай близко к типичной длине куска монтажа (для быстрого
бит-синхронного клипа — 0.3–0.7с; для более медленного — 0.8–1.5с). Скрипт
сканирует кадры (по умолчанию 8 fps выборки), считает резкость (Laplacian
variance), экспозицию, "здоровое" количество движения и бонус за лица, и не
предлагает сегмент, если внутри него в исходнике есть жёсткая склейка/резкая
смена кадра.

Если исходников много и они длинные — это самый долгий шаг; предупреди
пользователя, что анализ может занять время, пропорциональное суммарной
длине видео.

### 3. Собрать монтаж

```
python3 scripts/build_edit.py \
    --beats beats.json --clips clips.json --music song.mp3 \
    --out final.mp4 --resolution 1080x1920 --fps 30 \
    --max-duration 30 --style-seed 7
```

Что делает под капотом:
- строит сетку точек нарезки: обычно по downbeats, но на высокоэнергичных
  битах (энергия ≥ 0.7) — по каждому биту (плотная нарезка на дропе/пике —
  это и есть характерная черта премиум-монтажа);
- жадно раздаёт слотам лучшие ещё не использованные сегменты из `clips.json`,
  стараясь не повторять один и тот же исходник в соседних слотах;
- на энергичных слотах добавляет zoom punch и/или camera shake, на самом
  энергичном слоте всего монтажа — speed ramp (длительность слота при этом
  не меняется, бит не съезжает);
- между клипами вставляет переход, подобранный под энергию момента: flash/
  glitch на пиках, хард-каты и xfade-стили (wipe/zoom/dissolve/pixelize/…) на
  спокойных участках — см. `references/transitions_catalog.md` за полной
  таблицей и логикой выбора;
- обрезает музыку под длину монтажа с плавным затуханием в конце и
  мультиплексирует с готовым видеорядом (звук исходников не используется —
  под весь монтаж играет только трек).

`--resolution` задавай под площадку: `1080x1920` для Reels/TikTok/Shorts,
`1920x1080` для YouTube. `--max-duration` ограничивает длину, если трек
длиннее нужного клипа.

### 4. Проверка результата

Обязательно после рендера:
```
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1 final.mp4
```
и, если есть возможность, посмотри сам ролик (или хотя бы несколько кадров
через `ffmpeg -ss ... -frames:v 1 out.jpg`), чтобы убедиться, что переходы не
поломались и картинка не залипла на паузе. Прогон end-to-end без визуальной
проверки — не то же самое, что рабочий монтаж.

## Настройка "вайба" монтажа

- Больше энергии/агрессии -> понижай `energetic_threshold` в
  `build_cut_grid` (в `build_edit.py`) — тогда плотная нарезка будет
  включаться на большей части трека, не только на явном дропе.
- Другой набор переходов -> правь `choose_transition` в `build_edit.py`
  и/или список `XFADE_STYLES` в `transitions.py`.
- Разные версии монтажа из одного материала -> просто меняй `--style-seed`.

## Известные ограничения

- Скрипты последовательно кодируют каждый переход в отдельный проход ffmpeg
  (проще и надёжнее, чем один гигантский filter_complex), поэтому рендер
  длинного монтажа (много десятков катов) может занять заметное время —
  предупреждай об этом пользователя перед долгим прогоном.
- Детекция downbeat — наивная (группировка по 4 такта), не полноценный
  downbeat-tracking; для большинства поп/EDM/hip-hop треков в 4/4 этого
  достаточно, но на сложных тайм-сигнатурах может плыть.
- Аудио исходников не используется в финальном миксе — если пользователю
  нужны диалоги/синхрозвук поверх музыки, это отдельная доработка
  `build_edit.py` (добавить дорожку голоса отдельным `-map`).
