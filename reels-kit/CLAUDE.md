# Монтаж рилсов (локально, без платных сервисов)

Папки: `sources/` исходники (НИКОГДА не изменять и не удалять), `work/` промежуточное,
`plans/` планы нарезки, `output/` готовые MP4, `fonts/` шрифты, `music/` музыка.
Всегда `source .venv/bin/activate` перед запуском python-скриптов.

## Экспертный рилс (разговорное видео, русские субтитры)
1. `python transcribe.py sources/<файл>.mov` - получить `work/<файл>/transcript.txt` и `words.json`.
2. Прочитать `transcript.txt`. Выбрать ОДНУ главную мысль и набор отрезков до ~60 сек:
   крючок в начале, суть, короткий вывод. Убрать паузы, паразиты (э-э, ну, как бы), оговорки,
   повторы (оставлять лучший дубль). Не менять смысл, не склеивать так, чтобы фраза начиналась
   с середины предложения.
3. Записать план в `plans/<файл>.json`: `{"segments":[{"start":сек,"end":сек}, ...]}`
   (времена из transcript.txt, можно примерно: render сам притянет к границам слов).
4. `python render_expert.py sources/<файл>.mov plans/<файл>.json` - получится `output/<файл>_reel.mp4`.
5. Проверить результат: `python check_output.py output/<файл>_reel.mp4` (длительность, размер,
   громкость, кадры-превью). Посмотреть кадры-превью (читать картинки), сверить `.srt` с `.cuts.json`.

## Честные ограничения (говорить пользователю прямо)
- Выбор мыслей делается ТОЛЬКО по расшифровке. Картинку (кадры, лицо, свет) Claude не оценивает,
  пока не прочитал кадры-превью - и тогда оценивает только эти кадры.
- Расшифровка Whisper может ошибаться в именах и терминах: пользователь сверяет субтитры.
- Нельзя скачивать музыку из Instagram; музыку берёт пользователь (файл в `music/`).
- Никаких платных API, облачных сервисов и водяных знаков. Не ставить плагины/MCP без нужды.

## Рилс с мероприятия (под музыку)
1. `python contact_sheet.py sources/<файл>` для каждого исходника -> `work/<файл>/sheet_*.jpg`
   (кадр раз в секунду, подпись = секунда). Прочитать листы как картинки и выбрать удачные моменты.
2. `python beats.py music/<трек>.mp3` -> `work/beats_<трек>.json`. Сообщить темп; если он
   неправдоподобен (двойной/половинный), перезапустить с `--bpm`.
3. План `plans/<имя>.json` (формат в начале render_event.py): кадры по 2-4 доли, к концу короче.
4. `python render_event.py plans/<имя>.json` -> `output/<имя>_reel.mp4`, затем `check_output.py`.
Сказать прямо: видны только кадры раз в секунду, движение и звук исходника не оценивались.
